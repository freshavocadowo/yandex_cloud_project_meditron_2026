# MVP: эпикриз → JSON (50 полей). Архитектура и план на 3 дня

## 0. Быстрый старт (готово: сквозной rules-only конвейер, веб, БД, оценка)

```bash
python3.11 -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt
# корпус в репозиторий не коммитим: кладём в data/documents или задаём путь
python -m app.batch --input data/documents --output result --workers 8     # result/*.json + result_evidence/*.json
python -m eval.score --pred result --docs data/documents                   # валидность, полнота, точность по eval/gold
uvicorn app.api.main:app --port 8000                                       # веб: http://localhost:8000
CORPUS_DIR=data/documents python -m pytest -q
docker compose up --build                                                  # веб + PostgreSQL; пакет: docker compose run --rm batch
```

`result/<имя>.json` — ровно 9 групп / 50 ключей по шаблону, все значения — строки. `result_evidence/<имя>.json` — для каждого поля значение, цитата из обезличенного текста, её смещения и источник (`rule` / `llm` / `default`). Файл результата создаётся для 100% входов: при ошибке чтения пишется шаблон со значениями по умолчанию, причина — в `logs/failed.csv`. Повторный запуск пропускает документы с тем же sha256 и версией конвейера (`--force` — пересчитать).

| Модуль | Файл | Что делает |
|---|---|---|
| Loader | `app/ingest/loader.py` | .md/.txt; кодировки utf-8/utf-16/cp1251/koi8-r/cp866; нормализация: BOM, `\n`, NFC; sha256; коды ошибок; `discover()` пропускает скрытые/`~$`-файлы и ловит одинаковые имена .md/.txt |
| Anonymizer | `app/anonymize/pii.py` | ФИО (в т.ч. частицы «да», «фон», падежные формы фамилии далее по тексту), ДР (включая «условная дата 1206 г.»), возраст, № истории/карты, телефон, email, СНИЛС, полис, адрес → `[ФИО]`, `[ДР]`, `[ВОЗРАСТ]`, `[ID]`, … Исходные значения не сохраняются. `residual` — проверка остатков ПДн после маскирования |
| Segmenter | `app/segment/sections.py` | 15 типов разделов (diagnosis, exam, ecg, echo, xray, ca, labs, therapy, followup, …), ~90 синонимов заголовков; формы «ЭКГ», «ЭКГ:», «ЭКГ: текст», «ЭКГ. Текст», «Основная жалоба — текст»; неизвестный заголовок капсом → `other` |
| Schema | `app/schema.py` | группы и ключи в порядке шаблона, enum'ы, форматы, значения по умолчанию, `validate()` |
| Rules | `app/extract/rules.py` | все 50 полей: поиск в своём разделе, затем во всём тексте без «шумных» разделов (динамика, рекомендации); отрицания на уровне клаузы; первичная запись ЭКГ без контрольных; первые лабораторные значения; КАГ % → 0/1/2; препараты из назначений при выписке |
| Normalizer | `app/normalize.py` | даты (в т.ч. «10 сентября 2021», `16/09/21`) → `ДД.ММ.ГГГГ`, запятая → точка, римские → арабские, шкала стенозов |
| LLM | `app/extract/llm.py`, `prompts.py` | OpenAI-совместимый API (vLLM или YandexGPT), JSON-схема ответа, temperature=0; только для полей без цитаты от правил; 3 попытки с ошибками валидатора, иначе rules-only. Включается `LLM_BASE_URL` + `LLM_MODEL` |
| Validator | `app/validate.py` | значение проходит контракт, цитата совпадает с текстом (точно → без учёта пробелов → fuzzy ≥ 0.9), иначе значение по умолчанию + предупреждение |
| Batch | `app/batch.py` | пакет, потоки, кэш по sha256, `logs/failed.csv`, `--db` — запись в БД |
| DB | `app/db.py` | `documents` / `extractions` / `results`; PostgreSQL (`DATABASE_URL`) или SQLite по умолчанию; только обезличенный текст |
| API + веб | `app/api/main.py`, `web/index.html` | `POST /api/extract`, `GET /api/results/{id}`, `…/download`, `GET /api/documents`; страница: drag&drop, таблица по 9 группам, клик по полю подсвечивает цитату в тексте, скачивание JSON |
| Оценка | `eval/score.py`, `eval/gold/` | валидность, заполненность, доля значений с цитатой, точность по полям/группам против эталона |

### Результаты на 100 открытых документах (rules-only, версия 0.2.0)

| Метрика | Значение |
|---|---|
| Валидных JSON | 100 / 100 |
| Значений с цитатой-подтверждением | 100% непустых; заполнено 71% полей (остальное — «не указано»/0, когда в тексте нет сведений) |
| Точность на эталоне | 250 / 250 (5 документов × 50 полей) — эталон размечен разработчиком по тексту, **не медэкспертом**; нужна независимая разметка P4 |
| Сверка с наивными regex по корпусу (12 полей × 100 документов) | 0 расхождений |
| Сверка частот с текстом | STEMI 40 = I21.0–I21.2, NSTEMI 20 = I21.4, КАГ: Y 59 + R 6 = 65 разделов КАГ, ФП 11 = ФП на ЭКГ 11, … |
| Скорость | 100 документов — 0,6 с; 1000 (100 × 10) — 5,6 с на ноутбуке |
| Тесты | 68 (`tests/`): правила на вариантах формулировок, которых нет в корпусе, корпус, пакет, кэш, LLM-слияние с фейковым клиентом, API |

Корпус сильно шаблонный (~1000 уникальных строк на 100 документов), поэтому правила покрывают его полностью. Риск — формулировки контрольной выборки, которых нет в открытых документах: под них написаны тесты вариантов (`tests/test_rules.py`), а LLM-страховка закрывает поля, где правила ничего не нашли.

### Принятые решения по спорным полям (до ответа наставника, см. раздел 10)

| Поле | Решение |
|---|---|
| Бинарные без упоминания | `"0"` (кодовое правило ТЗ), явное отрицание — тоже `"0"`, но с цитатой |
| `type_acs` | «с подъёмом/элевацией ST» → STEMI; «без подъёма ST» + инфаркт → NSTEMI; нестабильная/прогрессирующая стенокардия → NA; без формулировки — по МКБ (I21.4 → NSTEMI, I21.0–3 → STEMI, I20 → NA) |
| `mi_localisation` | инфаркт без указанной стенки → N; нет инфаркта (стенокардия) → «не указано» |
| `atr_fibril` | диагноз; если там нет — ритм ФП/ТП в записи ЭКГ |
| `rg_pc` | только выявленный застой/отёк; «данных за застой нет» → «не указано» |
| `echo_zone` | фраза из текста без хвоста «ЛЖ» — как в примере ТЗ («Гипокинез нижней стенки») |
| `smoking` | фраза как в тексте: «Курит», «Не курит», «Бросил курить»; рекомендация «курение исключить» не считается |
| Препараты | только назначения при выписке (раздел рекомендаций); строка пункта целиком: «Тикагрелор 90 мг 2 раза в день» |
| `ca_date`, `ca_lad`, `rca` | только при `ca_fact = Y`; иначе «не указано» |

## 1. Цели (из ТЗ)
- Каждый входной `*.md` → `result/<то же имя>.json`, 9 групп / 50 ключей, все значения — строки.
- 1000 контрольных документов, пакетно, воспроизводимо, быстро.
- Метрики: валидность JSON, полнота, точность значений, подтверждаемость (фрагменты текста), скорость, демо.
- Доп.: БД анонимизированных данных, веб-страница (загрузка .md/.txt → страница результата + скачивание JSON).

## 2. Конвейер

```
.md/.txt ─► Loader ─► Anonymizer ─► Segmenter ─► Extractors ─► Merger ─► Normalizer ─► Validator ─► Writer
                                                 ├ Rules (regex+словари)              │             ├ result/*.json
                                                 └ LLM (vLLM, guided_json)            │             ├ result_evidence/*.json
                                                                                      └ retry/fallback  └ PostgreSQL
```

| Модуль | Что делает |
|---|---|
| Loader | чтение md/txt, автоопределение кодировки, sha256 для кэша |
| Anonymizer | замена ФИО, д.р., возраста, № истории болезни на токены (`[ФИО]`, `[ДР]`, `[ID]`). Даты госпитализации/исследований НЕ трогаем. В LLM и БД уходит только анонимизированный текст |
| Segmenter | деление на разделы по словарю синонимов заголовков (`ЭКГ:` / `ЭЛЕКТРОКАРДИОГРАФИЯ`, `Лабораторные исследования` / `ИССЛЕДОВАНИЯ` …). Нужен для правил «первичный осмотр», «первое измерение», «отдельная запись ЭКГ» |
| Rules | regex по разделу: даты, МКБ, Killip, АД/пульс/ЧДД/SpO2/рост/вес/ИМТ, ЭКГ, ЭхоКГ, лабы, КАГ (% → 0/1/2, окклюзия → 2), препараты по словарям (-олол, -статин, -прил/-сартан, клопидогрел/тикагрелор/прасугрел, апиксабан/ривароксабан/дабигатран/варфарин) |
| LLM | смысловые поля: art_hyper, atr_fibril, ckd, copd, dm, hf, tlt, type_acs, mi_localisation, smoking, echo_mr, echo_zone, rg_pc; страховка для полей, где правила ничего не нашли. Ответ строго по JSON-схеме: `{value, evidence}` на каждое поле, temperature=0 |
| Merger | приоритет: правило с evidence → LLM с evidence → «не указано»/0 |
| Normalizer | `ДД.ММ.ГГГГ`, запятая → точка, без единиц, АД `x/y`, Killip римские → арабские |
| Validator | pydantic-схема (ровно 50 ключей, enum'ы: Y/R/N, STEMI/NSTEMI/NA, A/I/L/N, 0/1/2); проверка evidence: фрагмент должен находиться в тексте (fuzzy ≥ 0.9), иначе значение сбрасывается — защита от галлюцинаций |
| Writer | `result/*.json` строго по шаблону; evidence отдельно (`result_evidence/*.json` + БД + UI) |

Гарантия полноты: при падении LLM — 3 ретрая с передачей ошибок валидатора, затем fallback на rules-only. Файл создаётся для 100% входов.

## 3. Пакетная обработка (воркер)
- `python -m app.batch --input data/ --output result/ --workers 32`
- asyncio + семафор на запросы к LLM; правила считаются локально.
- Кэш по sha256 (повторный запуск пропускает готовое), лог ошибок `logs/failed.csv`.
- LLM: vLLM на GPU-ВМ Yandex Cloud (OpenAI-совместимый API, structured output через `guided_json`), open-weights модель уровня Qwen2.5-14B-Instruct; альтернатива — YandexGPT через Foundation Models API. Выбор — по замеру на 20 документах в день 1.
- Цель по скорости: 1000 документов < 15 мин (проверить нагрузочным прогоном в день 2).
- Воспроизводимость: Docker Compose, зафиксированные версии модели/промптов, `PIPELINE_VERSION` в каждом результате БД.

## 4. БД (PostgreSQL, Yandex Managed PostgreSQL или контейнер)
```
documents  (id uuid, filename, sha256, anon_text, status, error, pipeline_version, created_at)
extractions(id, document_id, group_name, field, value, evidence, source rule|llm, created_at)
results    (document_id, json jsonb, created_at)
```
Хранится только анонимизированный текст.

## 5. API + веб
- FastAPI: `POST /api/extract` (файл) → `{id, json}`; `GET /api/results/{id}`; `GET /api/results/{id}/download`; `GET /api/documents`.
- Страницы: загрузка (.md/.txt, drag&drop) → результат: таблица по 9 группам, значение + фрагмент-подтверждение, подсветка фрагмента в тексте, кнопка «Скачать JSON».
- Стек фронта: статический HTML + JS (без сборки) — быстрее всего за 3 дня.

## 6. Структура репозитория
```
app/ingest  app/anonymize  app/segment  app/extract/{rules,llm,prompts}
app/normalize  app/validate  app/pipeline.py  app/batch.py  app/api  app/db
web/  eval/{gold,score.py}  data/  result/  docker-compose.yml
```

## 7. Оценка качества
- `eval/score.py`: валидность, полнота, exact match по полю/группе после нормализации, доля значений с evidence.
- Если эталона к 100 документам нет — медэксперт + QA размечают 30–50 документов (день 1–2).
- Отложенная выборка 20 документов для финальной оценки, промпты на ней не подгоняются.
