# Эпикриз → JSON

Прототип для пакетной обработки кардиологических выписных эпикризов пациентов, перенёсших острый коронарный синдром (ОКС). На каждый входной документ создаётся валидный JSON: 9 групп, 50 признаков о госпитализации, диагнозе, обследованиях и назначениях. Для каждого найденного значения сохраняется подтверждающий фрагмент текста.

Кейс Центра технологий для общества Yandex Cloud.

> **Только для исследований и демонстрации.** Все документы синтетические. Решение не предназначено для постановки диагноза и принятия клинических решений и не является системой поддержки клинических решений. Не загружайте в него реальные медицинские документы.

## Результат для проверки

- Папка [`result/`](result/) в корне репозитория. На каждый входной документ — отдельный файл с тем же базовым именем: `train-0001.md` → `result/train-0001.json`.
- Структура каждого файла совпадает с `participant-output-template-50.json`: 9 групп в порядке шаблона, внутри — все 50 ключей, все значения — строки.
- Подтверждающие фрагменты лежат отдельно, в [`result_evidence/`](result_evidence/), чтобы не нарушать формат шаблона.

Как получить результат на контрольной выборке, описано в разделе «[Запуск](#запуск)».

## Показатели на 100 открытых документах

Режим без нейросети (только правила), версия конвейера 0.2.0, ноутбук на Apple M1.

| Критерий | Результат |
|---|---|
| Валидность JSON | 100 из 100 файлов проходят проверку контракта (9 групп, 50 ключей, строки, допустимые значения) |
| Полнота документов | файл создан для 100% входов, в том числе для нечитаемых: тогда пишется шаблон со значениями по умолчанию, причина — в `logs/failed.csv` |
| Полнота полей | 71% полей заполнены значением из текста; остальные — «не указано» или 0, когда сведений в документе нет |
| Подтверждаемость | у 100% значений, взятых из текста, есть цитата, которая дословно находится в документе |
| Совпадение с эталоном | 250 из 250 значений (5 документов × 50 полей). Эталон размечен разработчиком, а не медицинским экспертом, поэтому это проверка согласованности, а не независимая оценка точности |
| Скорость | 100 документов — 0,7 с; 1000 документов — 5,8 с (8 потоков) |
| Тесты | 70 тестов: правила на формулировках, которых нет в открытом корпусе, весь корпус, пакетная обработка, API |

Повторить замер: `python -m eval.score --pred result --docs data/documents --evidence result_evidence`.

## Как это работает

```
.md / .txt / .docx
  → чтение      кодировки utf-8, utf-16, cp1251, koi8-r, cp866; .docx — абзацы и таблицы
  → обезличивание   ФИО, дата рождения, возраст, № истории, телефон, адрес → [ФИО], [ДР], …
  → разделы     ~90 вариантов заголовков → 15 типов: диагноз, осмотр, ЭКГ, ЭхоКГ, КАГ, анализы, назначения…
  → извлечение  правила (регулярные выражения и словари) по нужному разделу
                [необязательно] языковая модель — только для полей, где правила ничего не нашли
  → нормализация    даты, числа, единицы, римские цифры, шкала стенозов
  → проверка    значение соответствует контракту, цитата находится в тексте — иначе значение по умолчанию
  → result/*.json, result_evidence/*.json, база данных
```

Ключевые решения:

- **Каждое значение подтверждено.** Значение попадает в результат, только если к нему есть цитата, которая находится в исходном тексте (точно, без учёта пробелов или с похожестью не ниже 0,9). Без цитаты поле получает значение по умолчанию. Так модель или правило не могут выдумать значение.
- **Поиск в своём разделе.** «Первичный осмотр», «первое измерение» и «отдельная запись ЭКГ» из ТЗ определяются по разделам документа: контрольные ЭКГ, динамика и рекомендации не путаются с данными при поступлении.
- **Отрицания.** «Сахарный диабет отрицает», «данных за застой нет» распознаются на уровне фразы.
- **Обезличивание до извлечения.** В базу данных и (если включена) в языковую модель уходит только обезличенный текст. Исходные персональные данные нигде не сохраняются.
- **Воспроизводимость.** Без языковой модели результат детерминирован: один и тот же документ всегда даёт один и тот же JSON. Повторный запуск пропускает уже обработанные документы (по хэшу текста и версии конвейера).

### Формат подтверждающих фрагментов

`result_evidence/train-0001.json`:

```json
{
  "doc_id": "train-0001",
  "pipeline_version": "0.2.0",
  "fields": {
    "admission_date": {"value": "01.01.2020", "evidence": "Поступил 01.01.2020", "start": 110, "end": 129, "source": "rule"},
    "atr_fibril":     {"value": "0", "evidence": "", "start": -1, "end": -1, "source": "default"}
  }
}
```

`start` / `end` — смещения цитаты в обезличенном тексте, `source` — откуда значение: `rule` (правило), `llm` (модель) или `default` (сведений нет).

## Правила записи

Общие правила ТЗ соблюдаются полностью:

- даты — `ДД.ММ.ГГГГ` без времени; числа — без единиц, десятичная точка; давление — `140/90`;
- не найдено — «не указано»; показатели, которые не записаны явно (например, ИМТ), не вычисляются;
- бинарные коды: 1 — прямое указание, 0 — явное отрицание или отсутствие упоминания;
- лабораторные показатели — первый результат текущей госпитализации; давление и пульс — первичный осмотр; ЭКГ — отдельная запись ЭКГ;
- коронарография: Y / R / N; стенозы 0 / 1 / 2 — только при выполненной коронарографии, иначе «не указано».

Там, где ТЗ допускает разные толкования, приняты такие решения:

| Поле | Решение |
|---|---|
| `type_acs` | «с подъёмом ST» → STEMI; «без подъёма ST» и инфаркт → NSTEMI; нестабильная стенокардия → NA; без явной формулировки — по коду МКБ (I21.0–I21.3 → STEMI, I21.4 → NSTEMI, I20 → NA) |
| `mi_localisation` | инфаркт без указанной стенки → N; инфаркта нет (стенокардия) → «не указано» |
| `atr_fibril` | по диагнозу; если там нет — по ритму в записи ЭКГ |
| `rg_pc` | только выявленный застой или отёк; «данных за застой нет» → «не указано» |
| `echo_zone` | фраза из текста, как в примере ТЗ: «Гипокинез нижней стенки» |
| `smoking` | фраза из текста: «Курит», «Не курит», «Бросил курить»; рекомендация «курение исключить» не считается |
| Препараты | назначения при выписке; пункт целиком: «Тикагрелор 90 мг 2 раза в день» |
| `ca_date`, `ca_lad`, `rca` | только при `ca_fact = Y` |

## Запуск

### Docker (рекомендуется)

Нужен только Docker. Языковая модель не требуется.

```bash
git clone https://github.com/freshavocadowo/yandex_cloud_project_meditron_2026.git
cd yandex_cloud_project_meditron_2026

# пакетная обработка: документы кладём в data/documents/
mkdir -p data && cp -R /путь/к/документам data/documents
docker compose run --rm batch          # → result/, result_evidence/, запись в PostgreSQL

# веб-интерфейс и API
docker compose up --build -d           # → http://localhost:8000
docker compose down                    # остановить
```

Уже обработанные документы пропускаются. Чтобы пересчитать всё заново, удалите `result_evidence/`.

### Без Docker

Нужен Python 3.11 или новее.

```bash
python3 -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt

python -m app.batch --input data/documents --output result --evidence result_evidence --workers 8 --no-llm
python -m eval.score --pred result --docs data/documents --evidence result_evidence
uvicorn app.api.main:app --port 8000   # веб: http://localhost:8000, база — SQLite в out/meditron.db
CORPUS_DIR=data/documents python -m pytest -q
```

Параметры `app.batch`: `--force` — пересчитать закэшированные документы, `--no-llm` — не обращаться к модели, даже если она настроена, `--db` — сохранить результаты в базу (`DATABASE_URL`).

### Гибридный режим с языковой моделью (необязательно)

Без настроек проект работает только на правилах — так получены результаты в `result/`. Чтобы подключить модель через OpenAI-совместимый API, создайте `.env`:

```bash
LLM_BASE_URL=https://llm.api.cloud.yandex.net/v1      # YandexGPT или vLLM на своей ВМ: http://<vm>:8000/v1
LLM_MODEL=gpt://<folder>/yandexgpt/latest
LLM_API_KEY=...
```

Модель вызывается только для полей, где правила не нашли значение. Её ответ проходит ту же проверку цитаты; при ошибке делается до 3 повторов с сообщением об ошибке, затем — значение от правил. Сейчас этот путь проверен тестами на имитации модели; замеров качества и скорости на реальной модели пока нет.

## Демонстрация

Откройте http://localhost:8000.

- **Главная страница** — голова Джейсона Стетхэма. Перетащите на неё эпикриз `.md`, `.txt` или `.docx`: голова откроет рот, прожуёт файл, пока бэкенд извлекает признаки, и выдаст кнопку «держи, json», которая скачивает результат.
- **`/inspect`** — рабочий интерфейс для проверки: таблица 50 полей по группам с источником значения; клик по полю подсвечивает подтверждающий фрагмент в обезличенном тексте.

API:

| Метод | Что делает |
|---|---|
| `POST /api/extract` | загрузить файл (`multipart/form-data`, поле `file`) → JSON, цитаты, обезличенный текст |
| `GET /api/results/{id}` | сохранённый результат |
| `GET /api/results/{id}/download` | JSON-файл результата |
| `GET /api/documents` | список обработанных документов |
| `GET /api/schema` | группы, ключи, описания и режим работы (`rules-only` или `hybrid`) |

Документация API: http://localhost:8000/docs.

## Ограничения

- Эталон для проверки точности — 5 документов, размеченных разработчиком. Нужна независимая разметка медицинским экспертом на 30–50 документах.
- Открытый корпус очень шаблонный, поэтому правила покрывают его полностью. Риск — формулировки контрольной выборки, которых нет в открытых документах. Под них написаны тесты на варианты формулировок, а гибридный режим может закрыть поля, где правила ничего не нашли.
- Бинарный 0 означает «нет прямого указания в тексте», а не медицинское заключение об отсутствии болезни.

## Сравнение подходов

| Подход | Плюсы | Минусы |
|---|---|---|
| Правила и шаблоны (основа решения) | быстро, детерминированно, каждое значение объяснимо, работает без GPU | новые формулировки требуют новых правил |
| Классические NLP-модели (NER) | устойчивее к вариантам формулировок | нужна размеченная выборка, которой в кейсе нет |
| Большие языковые модели | понимают свободный текст без разметки | медленнее, дороже, могут выдумывать значения и ломать формат JSON |
| Гибрид (наш вариант) | правила дают точность и скорость, модель страхует пропуски, проверка цитат отсекает выдуманные значения | модель нужно развернуть и замерить |
